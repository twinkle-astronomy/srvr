# CSR + Explicit API Conversion

**Branch:** `csr-rpc-conversion` (new branch off `main`; cherry-pick useful pieces from the stale `origin/csr-rpc-conversion` spike)

## Context

The dashboard is a Dioxus Fullstack app: the server SSR-renders HTML, the browser downloads a WASM bundle and _hydrates_ it. `dioxus/fullstack` force-enables `dioxus-web/hydrate`, which means `dioxus_web::run()` always tries to read `window.initial_dioxus_hydration_data` at startup. Mounting any component into an empty `<div>` panics before component code runs — making isolated browser tests impossible without running the full server.

Converting to CSR (browser renders from scratch, no hydration) + a plain JSON API removes the forced hydration, lets `wasm-bindgen-test` mount pages in a real browser, and makes the client/server boundary inspectable with `curl`.

## What changes

| Area | Now | After |
|---|---|---|
| Serving | `dioxus::server::router()` / fullstack SSR | Axum serves `dist/` + JSON API; browser renders |
| RPC | 33 `#[server]` fns → opaque POST | Axum handlers at `/dashboard/...` returning JSON |
| Client | server fn stubs (generated by `#[server]`) | explicit `fetch` helpers in `src/frontend/api.rs` |
| Auth endpoints | axum-login forms (already plain Axum) | unchanged |
| `Cargo.toml` | `dioxus = { features = ["fullstack", "router"] }` | `dioxus = { features = ["router"] }` + `dioxus/web` in `web` feature, no `fullstack` |
| Browser tests | blocked (hydration panic) | unblocked; wire up wasm-bindgen-test tier |

## Phase 1 — Spike (validate serving, validate hydration is gone)

**Validate this before writing any API code.**

The riskiest assumption: dropping `dioxus/fullstack` lets a Dioxus WASM app mount in a browser without panicking.

Spike steps:
1. Remove `dioxus/fullstack` from `Cargo.toml`; add `dioxus/web` to the `web` feature.
2. Gut `server_fns.rs` to compile-stubs only (no calls to `#[server]` functions on the client).
3. In `main.rs` (server feature): replace `dioxus::server::router(frontend::App)` with an Axum router + a catch-all that returns `dist/index.html` for all non-API routes.
4. Build WASM: `cargo build --no-default-features --features web --target wasm32-unknown-unknown`
5. Build server: `cargo build --features server`
6. Load the app in a browser — confirm Dashboard loads (data will be missing, that's fine) with no hydration panic.
7. Write one `wasm-bindgen-test` that mounts `<Dashboard />` into a `<div>` and asserts it renders something — confirm it passes in headless Chromium.
8. Verify `dx serve --addr 0.0.0.0` still rebuilds and hot-reloads on file change. (`Dioxus.toml` keeps `default_platform = "fullstack"` so the CLI still builds server + WASM; confirm the CLI's hot-reload injection doesn't depend on `dioxus::server::router()` being present.)

If steps 6–7 pass: the conversion is unblocked. Continue to Phase 2. If not: capture the blocker and update the idea doc.

## Phase 2 — API layer (`src/api/`)

Add a new module `src/api/` (server-only, `#[cfg(feature = "server")]`).

**File layout:**
```
src/api/
├── mod.rs          — Axum Router combining all sub-routers; ApiError type
├── auth.rs         — check_auth, check_needs_setup
├── devices.rs      — get_devices, get_device_by_id, get_device_logs, delete_device,
│                     update_device_template, update_device_maximum_compatibility,
│                     get_render_context, get_render_context_for_template,
│                     get_virtual_render_context
├── templates.rs    — get_templates, get_template_by_id, get_default_template,
│                     create_template, copy_template, save_template, delete_template,
│                     get_screen_preview, get_screen_preview_for_template,
│                     get_template_preview, get_template_context
├── users.rs        — get_all_users, delete_user
├── prometheus.rs   — get_prometheus_queries_for_template, save_prometheus_query,
│                     delete_prometheus_query, execute_prometheus_query,
│                     execute_prometheus_queries
├── range.rs        — get_range_queries_for_template, save_range_query,
│                     delete_range_query, execute_range_query
└── http_sources.rs — save_http_source, delete_http_source, execute_http_source
```

**Route prefix:** `/dashboard/` (avoids collision with device API at `/api/display`, `/api/log`, etc.)

**Error type** in `src/api/mod.rs`:
```rust
pub struct ApiError(StatusCode, String);
impl IntoResponse for ApiError { ... }
impl From<sqlx::Error> for ApiError { ... }
```

**Handler pattern** (each file follows the same shape):
```rust
pub async fn get_devices(
    auth: AuthSession,   // axum-login extractor; 401 if unauthenticated
) -> Result<Json<Vec<Device>>, ApiError> {
    require_auth(&auth)?;
    let devices = crate::db::get_devices().await?;
    Ok(Json(devices))
}
```

`check_auth` and `check_needs_setup` skip the auth requirement (same as now). All others require a valid session.

**Tests:** integration tests inline in each handler file using the existing `#[tokio::test]` pattern. One test per handler covering: auth required, success path, and one error case.

Mount the API router in `main.rs` under `/dashboard`.

## Phase 3 — Client fetch layer

Replace the server-side `#[server]` impls with client-side fetch helpers.

New file: `src/frontend/api.rs` (gated `#[cfg(feature = "web")]`).

Shared helper:
```rust
async fn fetch_json<T: DeserializeOwned, B: Serialize>(
    method: Method, path: &str, body: Option<B>
) -> Result<T, FetchError> { ... }
```
Uses `gloo-net` — lighter than `reqwest` wasm, browser-native.

One public fn per endpoint, matching current server fn names:
```rust
pub async fn get_devices() -> Result<Vec<Device>, FetchError> {
    fetch_json(Method::GET, "/dashboard/devices", None::<()>).await
}
```

Update `src/frontend/store.rs`: replace every `server_fn_name().await` call with `api::fn_name().await`. No other store logic changes.

Delete the `#[server]` function bodies from `server_fns.rs`. Keep shared types (`ServerInfo`, `TemplateVar`) — move them to `src/models/mod.rs`.

## Phase 4 — Build switch

**Dev workflow goal**: `dx serve --addr 0.0.0.0` (or similar single command) still rebuilds and hot-reloads on file changes.

`Dioxus.toml` keeps `default_platform = "fullstack"` — this controls what `dx serve` builds and runs. We're only removing the `dioxus/fullstack` _Cargo feature_, not the CLI platform mode.

Changes:
- `Cargo.toml`: remove `fullstack` from `dioxus` features; add `dioxus/web` to `[features] web`. Remove `wasm-bindgen` from shared/default deps if it was only pulled in by fullstack.
- `src/main.rs`: replace `dioxus::server::router(frontend::App)` with:
  - `tower-http::ServeDir` for WASM bundle and assets — path from `DIOXUS_ASSET_DIR` env var in dev (dx sets this when running the binary), or `./dist` in prod
  - catch-all returning `index.html` from that dir for the SPA router
  - existing device API, auth routes, and the new dashboard API router
- Feature flags: audit `#[cfg(feature = "server")]` annotations; replace `FullstackContext::extract` with the axum-login extractor.
- Remove `server_fn_auth_middleware` (which guarded all POSTs); auth is now per-handler.

If the dev command changes, update `docs/setup.md`.

Definition of done:
```
cargo test --features server
cargo check --no-default-features --features web --target wasm32-unknown-unknown
```
Both must compile clean.

## Phase 5 — Browser test tier

Write browser-tier tests for:

## Open questions / tradeoffs

1. **Response envelope**: bare JSON (`Vec<Device>`) vs wrapped (`{data: [...]}`) — recommend bare; HTTP status carries the error signal.
2. **`execute_prometheus_queries` batching**: currently a loop server-side. Keep as a single POST endpoint accepting `Vec<PrometheusQuery>`.
3. **Hot-reload**: confirmed or worked around in Phase 1 spike before proceeding.
